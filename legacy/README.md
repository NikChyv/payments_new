# legacy/ — не выполнять

SQL-скрипты эпохи до миграций (июнь–июль 2026), когда схему меняли, вставляя
файлы в Supabase → SQL Editor. Оставлены ради истории: по ним видно, как
появлялись роли, привязка Telegram и сессии бота.

**Ни один из них не запускать — ни на проде, ни локально.** Всё их содержимое
давно в `supabase/migrations/`, причём в более строгом виде: с тех пор
закрывались права анонима, менялись политики, добавлялись проверки. Прогон
старого скрипта в SQL Editor откатит часть этого молча — `create or replace`
и `grant` сработают без ошибок.

| Файл | Что делал | Где живёт сейчас |
|---|---|---|
| `supabase_setup.sql` | роли, `staff`/`clients`, RLS, первые RPC по токену | `20260622000000_baseline.sql` и последующие миграции |
| `telegram_bot.sql` | колонка `clients.telegram_id` | baseline; правило «несколько фирм на один Telegram» — `20260828000001_shared_telegram.sql` |
| `telegram_sessions.sql` | таблица `tg_sessions` для диалога бота | baseline; права — `20260916000002_revoke_anon_tables.sql` |

Раньше они лежали в корне и в `supabase/` рядом с миграциями, и выглядели как
то, что «надо выполнить» (находка M11.7 ревью 09.09.2026). Перенесены 16.09.2026.

Что по-прежнему выполняется руками в SQL Editor — и только это:
`supabase/daily_reminder.sql` и `scripts/webhooks.sql` (RUNBOOK §2.3 и §5.2).

Легаси-страницы `index.html` и `app.html` остались в корне репозитория
намеренно: их публикует сайт (`deploy.yml`), на них могли остаться старые
закладки, и перенос сменил бы адрес.
